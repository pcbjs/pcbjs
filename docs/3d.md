# 3D view

What the 3D view draws, the generated part models, model files and their cache, and how the geometry is built.
Everything is built from the compiled board, so a click in 3D names the same item as in 2D. Fetching and fitting a model file is in models.md.

```ts
import { R0603, PinHeader } from '@pcbjs/lib'

const R1 = R0603({ value: '5.1k', model: { file: './models/R_0603_1608Metric.step' } })
const J2 = PinHeader(4, { model: { file: 'kicad:Connector_PinHeader_2.54mm.3dshapes/PinHeader_1x04_P2.54mm_Vertical.step', offset: [0, 0, 0], rotate: [0, 0, 0] } })
```

## What it draws

- Every pad, track, via, zone, graphic and text is a mesh from `items` in the site data: rings in board mm with id, kind, layers, net, ref and drill.
- Copper sits at the stackup's copper thickness, inner layers at their stackup depth.
- A plated hole has a barrel; a drill cuts board, copper and silk, a slot a stadium as the drill file routes it. NPTH holes cut the mask too.
- The mask is a slab with pad openings plus a skin over outer copper. Mask and silk colours come from the stackup: `Green`, `Black` or any CSS colour.
- A board placed with `reference()` is one translucent group under `References` in the layer list, see references.md.
- A layer hidden in the rail is hidden in 3D too.

## Interaction

| Input | Effect |
| --- | --- |
| drag, scroll | orbit, zoom |
| hover | names the part and pad or the net, kind and layer, lights the net |
| click | as in 2D: a pad, via or track pins its net, a body selects the part, empty space clears; opens the code, see editor.md |
| corner buttons | frame the board, top, bottom, iso; toggle grid, focus fade, exploded view |
| explode slider | gap 0 to 15 mm, 4 by default; a callout names each layer with thickness and material |
| hover a layer or callout | that callout opaque, every other layer dimmed |

- A frame takes the board, parts, references and exploded stack, never the grid, which takes the 2D grid's steps, see viewer.md. Toggling explode refits, keeping the camera direction; the slider keeps the framing; reduced motion jumps.
- Callouts stand in one column right of the stack, leaders from each layer's rightmost point. Parts and silk planes draw the outline with a faint grid.
- A selected part, pad or group or a pinned net fades the rest, see viewer.md. The popover under the focus fade button, remembered by the browser, sets:

| Option | Values |
| --- | --- |
| opacity | 25% by default, for substrate, mask, copper and bodies |
| colour | `Monochrome` greys the rest |
| surface | `Shaded`, or `Edges` for edges sharper than 30° and no faces |
| depth | `Grouped`, the default, one body; `Stacked`, every surface showing through |

## Model descriptors

| `model` | Used by |
| --- | --- |
| `{ kind: 'chip', part: 'R' \| 'C' \| 'L' \| 'D', size, marking? }` | chip passives; a resistor prints its code from `resistorCode`, such as `331` |
| `{ kind: 'led', size, color?, lens? }` | chip LEDs; colour from a value such as `green` |
| `{ kind: 'header', pins, rows, pitch, pinLength? }` | `PinHeader` |
| `{ kind: 'sot23', pins: 3 }` | three-pin SOT-23 |
| `{ kind: 'ic', w, h, height, color? }` | SOT-223, SOIC, TSSOP, QFN, QFP |
| `{ kind: 'box', w, h, height, reason? }` | no model: your own footprint without one, or a fetched model that did not download |
| `{ file, offset?, rotate?, scale?, fallback? }` | a STEP, glTF or WRL file; the stdlib's switches, crystals, connectors, modules and battery holder fetch theirs on first use |

- A `box` or no `model` is never solid: a dashed amber outline, its ref and `no model`, in the view and `pcbjs shot`. A referenced board leaves it out. `pcbjs model check`, `inspect` and README-fab count it as `no model`, the `--json` report as `models.missing`.
- A bare footprint, hole, test point, pogo pad, fiducial or mounting hole, as layout.md Silk refs defines it, defaults to `height` 0 and draws nothing. A zero size or height box counts as `no body`.
- Resistor tolerance comes from `fields={{ tolerance: '1%' }}`; `marking` overrides the code.
- Identical parts share geometry. The generators are in `packages/viewer/src/models`.

## Model files

| Key | Meaning |
| --- | --- |
| `file` | STEP or STP, glTF or GLB, or WRL by extension; `step` is an older name; `kind: 'step'` optional |
| `offset` | mm |
| `rotate` | degrees about x, y, z |
| `scale` | factor per axis |
| `fallback` | drawn until the mesh arrives; the stdlib keeps its generated model or body outline here |

- `file` is relative to the file holding the `model` literal, as an import: a footprint in `lib/parts.tsx` names `../models/x.step`. An absolute path or a `file:` URL is taken as it is.
- The frame is KiCad's, a `.kicad_mod` `(model ...)` line maps one to one: mm, origin at the footprint origin, x along footprint x, y along footprint -y, z up. Scale, then turn by the negated angles about x, y, z, then offset.
- Units: STEP carries its own; glTF is metres, y up; WRL is KiCad's 2.54 mm unit. A back side part turns over about its y axis.
- A missing file is the ERC warning `model-missing`; the view draws the fallback.
- A model box more than 1 mm past the courtyard or under a fifth of it, a top under the board face, an SMD body more than 0.2 mm into the board, or a height more than 1.6 times off `height` gets an amber outline in 3D and a line under `model` in the Part panel; a height off with a side matching reads `lying on its side?`.

## Conversion and cache

- `@pcbjs/step` converts each file once per content, in Node: STEP through `occt-import-js`, OpenCascade in WASM, glTF, GLB and WRL through its own readers. Curved faces within 0.02 mm and 0.3 rad; one mesh per file colour.
- The mesh is `.pcbjs/models/<hash>.bin`, the sha256 of content and options, shared by every board and process.
- The model box gives a footprint without `height` its height in `reference-collision` and a mate's default `gap`, see references.md.
- Site data per footprint: `step: { file, mesh, transform, bounds, courtyard, issue }`; `mesh` absent when the file is missing.
- Dev serves `/__pcbjs/model/<hash>`; `pcbjs build` copies used meshes to `models/<hash>.bin`.
- `occt-import-js` and OpenCascade are LGPL-2.1, loaded unmodified.

## Fetched on first use

| `file` | From |
| --- | --- |
| `kicad:<Lib>.3dshapes/<Name>.step` | an installed KiCad library, else KiCad's packages3D on GitLab at tag `10.0.7` |
| `lcsc:C123` | EasyEDA's model of the LCSC part, as `pcbjs model add lcsc:C123` |
| `https://…` | the URL |

- `${KICAD9_3DMODEL_DIR}/…`, which `pcbjs import` writes and `kicadModel()` keeps without KiCad, equals `kicad:…`.
- Files land in `.pcbjs/models/fetched/` under `kicad-10.0.7/`, `lcsc/` or the host, each with a line of URL, licence and date in `.pcbjs/models/fetched/LICENSES.md`. Delete a file to fetch anew.
- Every compile fetches, in a child process. A failed download keeps the dashed outline and prints `pcbjs: Blinky: SW1, Y1 show dashed outlines, the model did not download (…); run pcbjs model fetch`; the board still checks clean. `PCBJS_OFFLINE=1` skips every download.
- `pcbjs model fetch [entry...]` downloads what is missing. `model check` ends with `standard library: 24 parts, 24 with fetched models, 0 generated, 0 with no body`. `pcbjs doctor` shows the KiCad library and cache count.
- No model file ships in a package: @pcbjs/lib holds each model's source and alignment.

`pcbjs model add`, `align` and `check` are in models.md.

## How it builds

- Extrusions are jobs in `packages/viewer/src/scene/geometry.ts` on a web worker pool, in batches: copper and silk, mask skins, pours, holed slabs, which show whole first. A pour with many holes is triangulated per cell.
- `packages/export/src/items.ts` cuts in Node: each item less nearby drills, and `covered`, its part under the mask.
- Geometries are cached by a hash of their rings; a small board builds on the main thread.
